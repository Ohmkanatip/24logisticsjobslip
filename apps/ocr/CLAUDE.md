# CLAUDE.md — OCR อ่านเบอร์ตู้คอนเทนเนอร์ผ่าน LINE (`apps/ocr`)

## โปรเจกต์นี้คืออะไร
บอท LINE สำหรับคนขับ ~46 คน: ถ่ายรูปตู้ส่งแชท 1:1 → บอทอ่านเบอร์ตู้ (OCR) → ตรวจเช็คดิจิตตามมาตรฐาน **ISO 6346** → คนขับกดปุ่มยืนยัน → ระบบเติมเบอร์ตู้เข้าใบงานร่างให้

**สถานะ: โครงรอ (mock-first) — ห้าม deploy** · ทุกอย่างรันได้ทันทีโดยไม่มี key จริง
- OCR engine จริงยังไม่เคาะ → ใช้ mock (`OCR_PROVIDER=mock`)
- **การเขียนกลับ: เคาะแล้ว (28 ส.ค.) ทาง ③ d1 staging — implement จริงแล้ว** (`src/db/staging.js` + endpoint `GET /api/ocr/results` / `POST /api/ocr/pulled` + ด่าน `PULL_TOKEN`) · บอทไม่แตะชีท เว็บดึงเอง — ดู `ARCHITECTURE-OPTIONS.md`

## ⚠️ กติกาเหล็ก (ห้ามฝ่าฝืน)
- **เช็คดิจิตไม่ผ่าน = flag เท่านั้น — ห้ามเติมเข้าใบงานเอง** ระบบเสนอทางซ่อม (`suggestRepairs`) ให้คนเลือกได้ แต่ห้าม auto-ใช้
- **คนขับต้องกดยืนยันเสมอ — ไม่เขียนทับใบงานเงียบๆ** ทุกการเขียนกลับต้องมาจาก postback ยืนยัน และตรวจเช็คดิจิตซ้ำก่อนเขียนทุกครั้ง
- ห้ามมี secret/API key ในโค้ดหรือไฟล์ config — ตั้งผ่าน `wrangler secret put` เท่านั้น (placeholder ว่างอยู่ใน `.dev.vars.example`)
- stub ต้องซื่อสัตย์: ของที่ยังไม่ implement ตอบ `{ ok:false, reason:'not-implemented' }` — ห้ามแกล้งสำเร็จ (ยกเว้น mock ที่ติดป้าย `mock:true` ชัดๆ)
- logic ห้ามเรียก `Date.now()`/`new Date()` เอง — รับ timestamp เป็นพารามิเตอร์ (ให้ชั้นนอกส่งเวลาจริงเข้ามา)
- หมายเหตุกติกาโปรเจกต์แม่: V63.8 เลิกใช้ LINE "แจ้งเตือน" แล้ว — บอทนี้คือ "รับรูปจากคนขับ" คนละหน้าที่ ไม่ขัดกติกานั้น

## แผน 2 ระดับ
1. **① LINE chat bot MVP** — คนขับส่งรูปในแชท บอทตอบเบอร์+ผลตรวจ+ปุ่มยืนยัน · ยังไม่รู้ว่ารูปคู่กับใบงานไหน (ออฟฟิศ/คนขับเลือกทีหลัง หรือจับคู่จากทะเบียนรถ+เวลา)
2. **② LIFF** — คนขับเปิดหน้าเว็บใน LINE เลือกงานของตัวเองก่อนถ่าย → รูปผูกใบงานถูกใบอัตโนมัติ (`jobUid` ติดไปกับ postback ตั้งแต่ต้น)

## เช็คดิจิต ISO 6346 (implement จริงแล้วใน `src/iso6346/check.js`)
- ตัวอักษร 4 + เลข 6 + เช็คดิจิต 1 · ค่าตัวอักษร A=10…Z=38 **ข้ามพหุคูณของ 11** (ไม่มี 11/22/33) · ตำแหน่ง i=0..9 คูณ 2^i → รวม → mod 11 → ได้ 10 ใช้ 0
- เวกเตอร์ทดสอบบังคับ: **CSQU3054383 → เช็คดิจิต 3 (ผ่าน)** — ล็อกไว้ในเทสแล้ว

## ตารางเทียบ OCR engine — ตรวจราคาจริง 28 ส.ค. 2569
> **ปริมาณของเรา: ~60-100 ตู้/วัน ≈ 2,000-3,000 รูป/เดือน** · **สลับ engine = แก้ค่า `OCR_PROVIDER` ตัวเดียว** ไม่ต้องแตะโค้ดส่วนอื่นเลย

| Engine | ชั้นฟรี | เกินฟรีแล้วเท่าไหร่ | เหมาะ/ไม่เหมาะตรงไหน |
|---|---|---|---|
| ⭐ **Gemini 2.5 Flash-Lite** (Google AI Studio) | **1,000 คำขอ/วัน · 15/นาที · ไม่ต้องใส่บัตร · ไม่หมดอายุ** | — (ของเราใช้ไม่ถึง 10%) | **ฟรีจริงที่สุดสำหรับปริมาณเรา** · อ่านตัวเลขบนวัตถุจริงเก่ง · ⚠️ ชั้นฟรี Google อาจเอา input ไปปรับปรุงโมเดล (รูปตู้ไม่มีข้อมูลส่วนตัว ความเสี่ยงต่ำ แต่เจ้าของต้องรับทราบ) |
| **Google Cloud Vision** | 1,000 units/เดือน | **$1.50/1,000 units** (~50 บาท) → ของเรา ~2,000 units เกิน = **~100 บาท/เดือน** | OCR แบบคลาสสิก **ไม่ hallucinate** (ไม่แต่งเลขเอง) · ต้องตั้ง billing + บัตรเครดิต |
| **Cloudflare Workers AI** | 10,000 Neurons/วัน | $0.011/1,000 Neurons | **อยู่ค่ายเดียวกับ Worker เราอยู่แล้ว ไม่ต้องมี key ใหม่** · ⚠️ ต้องเช็คก่อนว่าแคตตาล็อกมีโมเดลอ่านรูปที่ใช้ได้จริง และ 1 รูปกิน Neurons เท่าไหร่ |
| **Qwen-VL** (Alibaba/OpenRouter) | แล้วแต่ช่องทาง | ~7-40 บาท/1,000 รูป | ถูกมาก อ่านวัตถุจริงเก่ง · ต้องคุม prompt กัน hallucinate |
| **Typhoon OCR** (SCB 10X) | มีชั้นฟรี ต้องเช็ค | หลักสิบ-ร้อยบาท | ทีมไทย ซัพพอร์ตไทย · เกิดมาเพื่อ**เอกสาร** ต้องลองกับรูปตู้จริงก่อน |
| **Self-host** (PaddleOCR/Tesseract) | ฟรีถาวร | ค่าเครื่อง | ข้อมูลไม่ออกนอกบ้านเลย · แต่ต้องมีเครื่องเปิดตลอด ที่ปริมาณนี้ไม่คุ้ม |

**ตาข่ายกัน AI แต่งเลขเอง:** ไม่ว่าใช้ engine ไหน ผลต้องผ่าน `extractCandidates` → `validate` (เช็คดิจิต ISO 6346) เสมอ
โมเดลแต่งเลขมั่ว โอกาสที่เช็คดิจิตจะบังเอิญถูกมีแค่ **~1 ใน 11** — และถึงผ่านก็ยังต้องให้คนขับกดยืนยันอีกชั้น

**วิธีเลือกที่แนะนำ:** อย่าเลือกจากตาราง — **ถ่ายรูปตู้จริง ~30 รูป (มุมเอียง แสงจ้า ตู้สกปรก ตอนกลางคืน) แล้วยิงเทียบทั้ง 3 เจ้า** ดูว่าเจ้าไหนอ่านถูกกี่รูป แล้วค่อยเคาะจากผลจริง

## 🔧 บั๊กที่แก้จากรีวิว adversarial (28 ส.ค. 2569 · เทส 92 → 111 เคส)
ทุกข้อ**พิสูจน์ด้วยการรันจริงก่อนแก้** และมีเทสล็อกกันย้อนกลับ:

| # | บั๊ก | ถ้าไม่แก้จะเป็นยังไง |
|---|---|---|
| 1 | ข้อความบอกคนขับว่า "บันทึกเข้าใบงานเรียบร้อย" ทั้งที่ทาง staging แค่พักรอเว็บดึง | คนขับเชื่อว่าเข้าระบบแล้ว ทั้งที่ออฟฟิศยังไม่ดึง — ผิดกติกา "ห้ามหลอก" |
| 2 | `WRITEBACK_PROVIDER` ค่าเริ่มต้นเป็น `mock` | ลืมตั้ง env = การยืนยันของคนขับหล่นลงถังที่ไม่มีใครอ่าน **หายเงียบ** → เปลี่ยนค่าเริ่มต้นเป็น `d1` |
| 3 | `markPulled` ของ D1 เป็น SELECT แล้วค่อย UPDATE | 2 คำสั่งแยกกัน = มีช่องให้แทรกกลาง **เบอร์เดียวถูกดึงไปใช้ 2 ใบ** → รวบเป็น UPDATE เดียวมี `WHERE status='confirmed'` |
| 4 | `insertResult` ของ D1 คืน `ok:true` เสมอ | D1 เขียนไม่สำเร็จแบบไม่ throw = คนขับเห็น "รับแล้ว" แต่ของไม่มีในฐาน |
| 5 | `listResults` memory เรียงคนละทางกับ D1 | เทสที่บอกว่า "interface เท่ากัน" หลอกตัวเอง — พฤติกรรมจริงต่างกัน |
| 6 | ลืมตั้ง `PULL_TOKEN` = เปิดโล่งให้ใครก็อ่าน/ติดธงผลได้ | **ขึ้นของจริงแล้วลืม = ประตูเปิด** → ตอนนี้ผ่อนผันเฉพาะโหมดทดลอง ของจริงไม่มี token = ปฏิเสธ 503 |
| 7 | ไม่มี CORS เลย | เว็บ jobslip อยู่คนละโดเมน — **เบราว์เซอร์บล็อก ดึงผลไม่ได้เลยสักครั้ง** (สถาปัตยกรรมที่เจ้าของเคาะพังทั้งเส้น) → เพิ่ม `ALLOW_ORIGIN` + preflight |
| 8 | `/api/ocr/pulled` ตอบ 409 ทุกกรณีที่ไม่สำเร็จ | เว็บแยกไม่ออกว่า "ไม่มีแถวนี้" กับ "คนอื่นดึงไปแล้ว" → 404 / 409 แยกกัน |

**ตรวจแล้วไม่ใช่บั๊ก:** ข้อกล่าวหาว่า `suggestRepairs` ตายสนิทในเส้นทางจริง — **ไม่จริง** พิสูจน์แล้ว `CSQU3054384` → เสนอ `CSQU3051384` ได้ปกติ

## 🧬 Mutation test — พิสูจน์ว่าเทสไม่ใช่เทสหลอก
```bash
node tests/mutation.js     # หรือ npm run mutation
```
**หลักการ:** "เทสผ่าน" ไม่ได้แปลว่าเทสดี — อาจเป็นเทสที่ไม่ว่าโค้ดผิดยังไงก็ผ่าน
เครื่องมือนี้ **แกล้งฝังบั๊ก 18 ตัวลงโค้ดจริง → รันเทส → เทสต้องตก** แล้วคืนโค้ดต้นฉบับให้อัตโนมัติ (`finally` เสมอ + ตรวจซ้ำท้ายสุด + รันเทสปิดท้ายพิสูจน์ว่าไม่มีบั๊กค้าง)

- ✅ **ฆ่าได้** = ด่านนั้นเชื่อถือได้จริง
- 🕳 **SURVIVED** = ฝังบั๊กแล้วเทสยังเขียว → **เทสมีรู ต้องเพิ่มเทส** (exit 1)
- ⚠️ **MUTATION-BROKEN** = หา find ไม่เจอ/เจอหลายที่ → ต้องมาแก้รายการ mutation (โค้ดเปลี่ยนไปแล้ว)

**สถานะ: ฆ่าได้ 18/18** · รอบแรกรอด 3 ตัว = เจอรูจริงในเทส แล้วอุดจนครบ
**แก้โค้ดในไฟล์ที่ mutation อ้างถึงแล้ว ต้องรันตัวนี้ด้วยเสมอ** ไม่ใช่แค่ `npm test`
