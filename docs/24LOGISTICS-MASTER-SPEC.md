## ตัดทิ้งถาวร (เคาะแล้ว ไม่วนกลับมาคุย)
- ❌ แอปลง App Store / Play Store — ใช้ LINE แทน
- ❌ สร้าง marketplace / backhaul matching — เป็นผู้ใช้แพลตฟอร์มคนอื่นแทน
- ❌ โมดูลอู่+สต็อกอะไหล่เต็มรูปแบบ — ใช้แค่แท็บซ่อม+เตือนเอกสาร
- ❌ ซื้อระบบสำเร็จรูป (The Trucker ~240K/ปี · Forward Insight ~216K/ปี ที่ 60 คัน) — ทำเองต้นทุน ~10K/ปี และเจาะลึกกว่า

## กติกากรองฟีเจอร์ (ใช้ตลอดไป — กันระบบรกแบบที่เห็นใน demo คู่แข่ง)
เพิ่มฟิลด์/ฟีเจอร์ได้ต่อเมื่อตอบได้ **ทั้ง 2 ข้อ**:
1. ใครเป็นคนกรอก — และเขายอมกรอกจริงไหม
2. ใครเอาข้อมูลนี้ไปใช้ตัดสินใจอะไร
ตอบไม่ได้ข้อใดข้อหนึ่ง = ตัด · ความเรียบของระบบคือฟีเจอร์อันดับหนึ่ง

## การตัดสินใจล่าสุด (เคาะ 22 ส.ค.)

1. **ผู้ใช้หลักของหน้าตีราคา+จ่ายงาน = คนในออฟฟิศ** (ไม่ใช่เจ้าของ) → ผลต่อการออกแบบ: UI ต้องเรียบสุด ไม่มีศัพท์เทคนิค, ต้องมี role/login ให้พนักงานออฟฟิศ (เฟส 0 ให้ตรวจว่า role ที่มีจริงรองรับไหม), ทำคู่มือ 1 หน้าเมื่อเสร็จ
2. **ค่าเบิกคนขับ (งาน ③): พี่ชายเป็นผู้อนุมัติ** — คิวอนุมัติออกแบบให้พี่ชายใช้คนเดียวได้เร็ว (ปุ่มใหญ่ อนุมัติ/ปฏิเสธ จากมือถือได้)
3. **เริ่มงาน ① ทันที** — สถานะ: กำลังทำ

# ส่วน B: SPEC งาน ① — เชื่อมจ่ายงาน → ใบงานร่าง

> ให้ Claude Code อ่านทั้งส่วนนี้ก่อนเขียนโค้ดบรรทัดแรก · ทำทีละเฟส หยุดรอยืนยันก่อนขึ้นเฟสถัดไป

## เป้าหมาย

```
ตอนนี้:   รถวิ่งเสร็จ → พี่ชายพิมพ์ใบงานย้อนหลังทุกช่อง
เป้าหมาย: ตีราคา → จ่ายงาน → [ใบงานร่างในชีท] → รถวิ่ง
          → พี่ชายเติมช่องที่เหลือ (เบอร์ตู้/ลาน) → กดยืนยัน → วงจรบิล V63.7 เดิม
```

ช่อง "เบอร์ตู้" ที่ว่างในร่าง = จุดเสียบ OCR ของงาน ③ (ยังไม่ทำตอนนี้)

## กติกาห้ามละเมิด

1. **ชีทคือบ้านของข้อมูล** — ห้ามสร้างฐานข้อมูลใหม่
2. **ใบงานร่างห้ามไหลเข้า บิล/แดชบอร์ด/ค่าเที่ยว/ลูกหนี้** จนกว่ายืนยัน — ทุกจุดที่รวมยอดต้องกรองสถานะร่างออก
3. **ห้ามรื้อ flow เดิม** — พี่ชายสร้างใบงานตรงได้เหมือนเดิม (งานด่วนมีแน่) ระบบร่างคือทางเพิ่ม ไม่ใช่ทางบังคับ
4. id/ฟังก์ชันใหม่ใช้ prefix `dr` ทั้งหมด — grep ตรวจชนก่อน commit ทุกครั้ง (บทเรียน V59/V60)
5. ก่อนใส่สูตร/คอลัมน์ใหม่ เรียก `ensureTabRoom_()` เสมอ (บทเรียน 11 ส.ค.)
6. ทุก act ใหม่ผ่านด่าน rate limit + `safeText_` เดิม
7. Feedback หน้าเต็มจอใช้ toast ไม่ใช่ `#msg` (บทเรียน V63.3)
8. ทำบน branch `feat/draft-jobs` แล้ว merge (กติกา V58)
9. ห้ามใส่ secret ในโค้ด

## เฟส 0 — สำรวจก่อน ห้ามเขียนโค้ด

อ่านโค้ดจริงแล้ว**รายงานก่อน**:
1. ชื่อแท็บใบงาน + คอลัมน์ทั้งหมด (พร้อม index)
2. act ทั้งหมดใน Apps Script + แพทเทิร์นเขียนแถวใหม่
3. ค่า enum สถานะใบงานที่มีจริง + ทุกจุดในโค้ดที่กรองตามสถานะ
4. `uid` เดิมสร้างยังไง ที่ไหน
5. แท็บคนขับ: กี่คน คอลัมน์อะไร มี driverId ไหม
6. จุดที่แดชบอร์ด/ค่าเที่ยว/บิลดึงข้อมูลใบงาน (ที่ที่ต้องเพิ่มตัวกรองร่าง)

> **โครงจริงในโค้ดชนะสเปกนี้เสมอ** — ขัดกันให้ถาม ห้ามเดา

## เฟส 1 — Master คนขับชุดเดียว

1. แท็บคนขับในชีท: ถ้าไม่มี `driverId` → เพิ่ม (รูปแบบ `D001`+) — id นี้จะใช้ผูก LINE ในงาน ③ ด้วย
2. เทียบ RAW ในแอปจ่ายงาน (49 แถว) กับชีท (~46 คน): รายงานส่วนต่าง / ทะเบียนซ้ำ (เจอ 69-8427 สองแถว) / "(ไม่ระบุชื่อ)" 4 คน → **ส่งรายการให้เจ้าของเคาะ ห้ามลบ/รวมอัตโนมัติ**
3. act ใหม่ `drDriverlist` — คืน `[{driverId, ชื่อ, ทะเบียน, active}]`

**เกณฑ์ผ่าน:** drDriverlist ตรงกับชีท 100% · ไม่มีการแก้ข้อมูลโดยไม่ผ่านเจ้าของ

## เฟส 2 — Apps Script: ใบงานร่าง

**act ใหม่ 3 ตัว:**

`drSave` — สร้างร่าง
- รับ: วันที่, ลูกค้า, ต้นทาง, ปลายทาง, driverId, ทะเบียน, ราคาเสนอ, ค่าเที่ยวประมาณ, ระยะทาง, หมายเหตุ, เหตุผลOverride(ถ้ามี)
- เขียนลง**แท็บใบงานเดิม** สถานะ = `ร่าง` · สร้าง uid ตามแพทเทิร์นเดิม · ช่องที่ยังไม่รู้ (เบอร์ตู้/ลาน/Job.Ref/B/L) เว้นว่าง · ตอบ uid กลับ

`drConfirm` — ยืนยันร่าง
- รับ uid + ค่าที่เติม/แก้ · เปลี่ยนสถานะเป็นสถานะเริ่มต้นปกติ (ตามที่เฟส 0 เจอ)
- **เงินคนขับ:** คำนวณค่าเที่ยวจากเรทตาราง — ถ้าต่างจากค่าประมาณตอนจ่ายงานเกิน **200 บาท** ตอบคำเตือนพร้อมตัวเลขทั้งคู่ ให้คนเลือก ห้ามเลือกเอง
- บันทึกเวลา+ผู้ยืนยัน

`drCancel` — สถานะ `ยกเลิกร่าง` (ไม่ลบแถว — ตามหลักถังขยะเดิม)

**สิทธิ์:** drSave = ทุก role ล็อกอิน · drConfirm/drCancel = แอดมิน + คนวางบิล

**ตัวกรอง (สำคัญสุด):** ไล่ทุกจุดจากเฟส 0 ข้อ 6 เพิ่มเงื่อนไขตัด `ร่าง` + `ยกเลิกร่าง` ออก แล้วลิสต์รายงานว่าแก้ที่ไหนบ้าง

**เกณฑ์ผ่าน:** สร้างร่าง 1 ใบ → ยอดแดชบอร์ด/ค่าเที่ยว/บิล **ไม่ขยับแม้แต่บาทเดียว** → ยืนยันแล้วค่อยขยับ

## เฟส 3 — แอปจ่ายงาน (24logistics_app.html)

1. ตัด RAW → โหลดจาก `drDriverlist` ตอนเปิด (cache localStorage + ปุ่มรีเฟรช)
2. ปุ่มจ่ายงาน → ยิง `drSave` → โชว์ uid ใน toast
3. **ตาข่ายกันหาย (แพทเทิร์น `#b2Sess`):** ยิงไม่สำเร็จ → เก็บในเครื่อง + รายการ "⏳ รอส่ง" + ปุ่ม ⟳ ส่งซ้ำ
4. ระบบแนะนำคนขับ/Override/ราคาพื้น/audit เดิม **คงไว้ทั้งหมด** (การย้ายคะแนนภาระไปอ่านจากชีท = งานถัดไป ยังไม่ทำ)

**เกณฑ์ผ่าน:** จ่ายงาน → แถวร่างโผล่ในชีทใน 5 วิ พร้อม uid/driverId ถูก · ปิดเน็ตจ่ายงาน → เข้าคิวรอส่ง ไม่หาย ไม่ซ้ำ

## เฟส 4 — เว็บใบงาน: มุมมองร่างรอยืนยัน

1. ปุ่ม "🗂 ร่างรอยืนยัน (N)" เห็นชัดตอนเปิดหน้า
2. รายการ: วันที่ · ลูกค้า · คนขับ · เส้นทาง · ราคา · ค่าเที่ยวประมาณ · อายุร่าง (เกิน 48 ชม. ขึ้นสีเตือน)
3. กดร่าง → ฟอร์มเดิมพร้อมค่าที่มี → เติมช่องว่าง → [✅ ยืนยัน] [🗑 ยกเลิก]
4. ถ้า drConfirm เตือนค่าเที่ยวต่าง → โชว์สองตัวเลขให้เลือก
5. เฉพาะแอดมิน + คนวางบิล

**เกณฑ์ผ่าน:** วงจรเต็ม จ่ายงาน→ร่าง→เติม→ยืนยัน→วางบิลได้เหมือนงานสร้างตรง

## เฟส 5 — ของเล็ก 3 ชิ้น (ผ่านกติกากรองแล้ว)

**5.1 จุดเปิดตู้ (ช่องที่ 3)**
- ใบงานตอนนี้มีลานรับ/ลานคืน → เพิ่ม "สถานที่ส่ง/เปิดตู้" ให้ครบ รับ→เปิด→คืน
- ใครกรอก: พี่ชาย (รู้อยู่แล้วตอนจด) · ใครใช้: คิดเรท/ระยะทาง/อนาคตผูก GPS

**5.2 เตือนเอกสารรถหมดอายุ**
- แท็บ `รถ` (สร้างถ้ายังไม่มี): ทะเบียน · ประเภท(หัว/หาง) · วันหมดอายุ ภาษี/พรบ./ประกัน/ตรวจสภาพ
- สูตรไฮไลต์: แดง=เลยกำหนด · ส้ม=ภายใน 30 วัน + แถบสรุปบนแดชบอร์ดว่ามีกี่รายการใกล้ครบ
- ใครกรอก: ปีละครั้งต่อคัน · ใครใช้: กันโดนปรับ/ประกันขาด

**5.3 ราคาน้ำมัน ณ วันงาน — อัตโนมัติเท่านั้น**
- Apps Script time-trigger วันละครั้ง ดึงราคาดีเซล (แหล่ง: ราคากลางที่ scrape/fetch ได้เสถียร — ให้เสนอแหล่งมาก่อน 2-3 ตัวเลือกพร้อมข้อดีเสีย แล้วรอเคาะ) → เก็บแท็บ `ราคาน้ำมัน` (วันที่, บาท/ลิตร)
- ใบงานอ่านราคาของวันงานมาแสดง/เก็บ — **ห้ามมีช่องให้กรอกมือ** ถ้าดึงอัตโนมัติไม่ได้ให้ตัดฟีเจอร์นี้ทิ้ง
- ใครกรอก: ไม่มีใคร (เครื่องทำ) · ใครใช้: เจรจา fuel surcharge กับลูกค้าในอนาคต + หน้ากำไร/คัน

## Edge cases (เขียนเทสต์ให้ครบ)

| เคส | พฤติกรรมที่ถูก |
|---|---|
| กดจ่ายงานซ้ำ (มือลั่น) | dedupe: driverId+วันที่+ลูกค้า+ราคาเดิมภายใน 2 นาที → คืน uid เดิม ไม่สร้างใหม่ |
| ยืนยันร่างที่ยืนยันแล้ว | error ชัดเจน ไม่เขียนซ้ำ |
| สองคนยืนยันพร้อมกัน | คนหลังได้ "ถูกยืนยันแล้วโดย..." |
| ร่างของคนขับที่ปิดใช้งานแล้ว | ยืนยันได้ + ขึ้นเตือน |
| งานด่วนสร้างตรง | เหมือนเดิม 100% |
| แอปออฟไลน์ | คิวรอส่ง+ส่งซ้ำ ไม่หาย ไม่ซ้ำ (server dedupe กัน) |
